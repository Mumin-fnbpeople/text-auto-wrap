# text_auto_wrap 0.1.1 maintenance and 0.2.0 discovery design

## Status and release boundary

`v0.1.0` is an immutable, already published release.  Its annotated source
tag resolves to `d0db6ee23ba6c2e0e5a030f3ff645c9f4ed3ad9f`; no work in this
design retags, deletes, or otherwise changes it.  Development starts from
`main` at `41ed29cad0cf695620b45c6530ec5e0ee3cd4259`, which contains the
future OIDC publishing workflow.

The work is deliberately split into two releases:

* **0.1.1:** a backwards-compatible maintenance release.  It adds no public
  API, changes no documented exact-first/native-fallback contract, and does
  not publish or push a tag without a later explicit authorization.
* **0.2.0:** a separately approved feature release.  This document records
  discovery constraints only; it does not add telemetry, corpus data,
  benchmarks, or public API in the 0.1.1 branch.

The existing untracked `.DS_Store`, `lib/.DS_Store`, and `lib/src/.DS_Store`
are user/environment files.  They remain untouched and unstaged.

## 0.1.1 scope

### Reliability and regression coverage

M2 validates every public BudouX score accumulation.  An individually finite
custom weight that makes a base or inference score non-finite produces the
existing typed model-configuration failure rather than silently influencing a
prediction.  Bundled preset data is unchanged.

M3 adds an ephemeral range-measurement cache for one authoritative calculation
operation when `measurementCacheKey` is null.  It never survives that
operation, so it does not claim cross-call reuse or support for a measurer
whose answer changes during the same operation.  Cache-keyed behavior remains
unchanged.

M8 adds direct tests for `NaN` and both infinities in fallback penalties and
`PhraseModelLevel.penalty`.  M9 separates forged calculator fixtures so
metadata mismatch and stale overflow validation are independently reached.
M10 adds plain-text first-frame and renderer controller lifecycle coverage,
including pre-post-frame observation and detach/dispose cancellation.  M11
tests repeated unmeasurable-placeholder fallback and a later valid recovery.
M12 adds repository-owned packaged fallback-font coverage and a web DPR
change/repaint regression, without claiming a pre-existing DPR defect.

All tests retain the settled fidelity behavior: whitespace candidates whose
published source ranges/content do not match the transformed or native
paragraph are rejected to native geometry with
`invalidRuntimeMeasurement`; no source whitespace is deleted.

### Documentation and CI

The Korean and English model cards state that the three tables and metadata
describe each preset's **bundled model data**, not the complete runtime
package.  They describe nested levels as cumulative training targets, not a
runtime-prediction invariant.  README custom-predictor snippets become
standalone minimal implementations using allowed whitespace-run-end offsets,
including repeated whitespace.

CI declares `permissions: contents: read`.  The tag publishing workflow keeps
the required `id-token: write` permission.  Public dartdoc is prioritized by
entry-point and user-implemented surface: widget/controller, engine entry
points and results, model/predictor contracts, and strategy contracts.  The
work documents meaningful behavior rather than mechanically decorating every
symbol; package-scoped dartdoc remains warning-free.

README, model-card, and NOTICE attribution stay intact, as do the experimental
model limitations.  The package continues to have no `textwrap.dart`
dependency.  The release archive must continue excluding `.tooling`,
credentials, coverage, screenshots, temporary clones, `.DS_Store`,
`.superpowers`, and internal planning documents.

### Compatibility, error handling, and verification

Production changes follow focused RED -> GREEN -> affected-suite evidence.
The current Flutter 3.47.4 behavior and Flutter 3.38.1 compatibility remain
mandatory.  A failure during the work uses systematic debugging before a
repair is proposed.  Each independently reviewable change receives an
independent code review; Critical and Important findings are resolved before
the next change.

Before a potential 0.1.1 release, verify format, analysis, full tests on both
supported toolchains as applicable, example web build, package-scoped dartdoc,
`pana --no-warning`, and `flutter pub publish --dry-run`, including its exact
archive contents.  No tag push is used to test publishing.

### Existing rulings retained

The following ledger rulings are binding unless a new evidence-backed decision
is explicitly recorded with its cost:

1. Work occurs in the requested checkout; the cost is direct default-branch
   history rather than an isolated branch.
2. `PhraseModel` remains non-const to preserve defensive copying and immutable
   validated configuration; const-expression construction is the cost.
3. The original parser RED evidence has the recorded historical exception;
   strict historical provenance cannot be recreated.
4. Inserted newlines stay inside cloned `TextSpan.text` so one original
   semantic/gesture unit remains one unit; the internal tree differs from a
   separate-newline-leaf design.
5. The public API compile check remains honestly immediately green; the cost is
   no manufactured RED transcript and no unsupported renderer export.
6. `.pubignore` excludes internal process documents; archive consumers lose
   those artifacts while repository history retains them.
7. The historical Task 9 report remains untracked from the latest source tip;
   it is recoverable from history/local ignored state.
8. Flutter 3.38.1 is the executable minimum-floor evidence; the anomalous
   3.38.0 bundle remains excluded, and compatibility bridges carry a small
   semantic-parity maintenance cost.
9. A deliberately malformed native placeholder/span state that Flutter cannot
   measure produces no fabricated result or controller commit; valid-content
   native fallback still publishes real geometry.  The cost is losing a
   synthetic fallback diagnostic for invalid native input.

## 0.2.0 discovery only

Three possible features require a new public/product decision and are excluded
from 0.1.1:

1. **Corpus evaluation and model cards.** Define consented, redistributable
   Korean/English app-text corpora; publish methodology, segmentation and
   acceptance metrics, failures, and model-card provenance.  No accuracy claim
   should be made from a private or unreviewable corpus.
2. **Privacy-safe diagnostics hook.** Explore an opt-in, local callback that
   exposes only structural outcomes (semantic/native choice, fallback reason,
   cache hit) and never text, offsets, model feature values, recognizers, or
   placeholder identity.  Decide callback lifetime, rate control, error
   isolation, and whether even aggregate counters are appropriate.
3. **Golden/performance trend CI.** Define fixed-font, platform-aware golden
   baselines and non-flaky performance indicators.  Decide storage, review
   thresholds, web/browser matrix, and how a measurement trend is presented
   without turning shared-CI wall time into a correctness gate.

The 0.2.0 design must choose API names and semver impact only after these
policy and maintenance costs have been reviewed.  It should be written and
approved independently before implementation.

## Delivery sequence

1. Create an isolated worktree after this design is reviewed and approved.
2. Write a task plan, then perform 0.1.1 changes as small TDD/reviewed units.
3. Update the progress ledger after every unit with task, RED/GREEN evidence,
   review verdict, deferred minors, rulings, and costs.
4. Run final release verification and decide integration through the required
   development-branch completion procedure.
5. Leave version bump, tag creation, GitHub Release, and pub.dev publishing
   pending explicit user approval.
